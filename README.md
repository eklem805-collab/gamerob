# Cyber Drift — 3D Low-Poly Neon Hover Racer (Android)

Готовый к установке APK лежит в корне репозитория: **`game.apk`** (~478 KiB).

Это полноценный 3D-рейсер от третьего лица: неоновый каньон, парящий ховеркрафт,
энергосферы, кристаллы-препятствия, дрейфовая физика, нитро и подсчёт очков.
Вся геометрия генерируется кодом на старте — ни одного скачанного ассета.
Рендер — собственный минимальный движок на **OpenGL ES 2.0**, собранный в нативную
библиотеку `libcyberdrift.so` (arm64-v8a) и запускаемый через `NativeActivity`
(`android:hasCode="false"`, без Java-кода и без NDK-рантайма).

## Установка

```bash
# по USB (ADB) — самый простой путь
adb install -r game.apk

# либо скопируйте game.apk на планшет и откройте файл,
# разрешив установку из этого источника
```

Проверка подписи и содержимого:

```bash
$ANDROID_HOME/build-tools/<ver>/aapt2 dump badging game.apk
```

## Управление

* **Левая часть экрана** — виртуальный стик: аналоговое руление (тяните влево/вправо),
  кнопки ◀ ▶ работают как альтернатива.
* **NITRO** (правая нижняя кнопка) — ускорение, тратит энергию; энергия восстанавливается
  при сборе сфер и в дрейфе.
* **BRAKE** (кнопка рядом) — сброс скорости перед кристаллом/барьером.
* **Кнопка паузы** в правом верхнем углу, тап в любом месте на паузе — продолжить.

## Геймплей

* Трасса бесконечная, процедурная: изгибы, подъёмы, сужение коридора.
* Энергосферы (`+очки`, `+энергия`), щит (синяя сфера — гасит одно попадание),
  кристаллы и барьеры (столкновение — потеря скорости, тряска, вспышка).
* Дрейф: чем резче поворот на скорости, тем больше искр, множитель и очки.
* Скорость 62 м/с в крейсере, до 128 м/с на нитро; HUD показывает км/ч, очки,
  энергию, щиты, дистанцию и миникарту.

## Адаптивность

HUD масштабируется от размера экрана: проверено на 16:10 (1280×800) и 4:3 (1024×768).
Все подписи и кнопки прогоняются через `cd_ui_text_fit()` — текст не выходит за панель
ни при каком соотношении сторон. Скриншоты: `docs/screens/`.

## Сборка из исходников

Нужны: Python 3.11, `zig` (кросс-компилятор C → aarch64-linux-android),
`aapt2`, `android.jar` (API 33, лежит в `third_party/`).

```bash
pip install ziglang aapt2 apksigtool

ZIG=$(python3 -c "import ziglang,os;print(os.path.join(os.path.dirname(ziglang.__file__),'zig'))") \
  python3 tools/build_apk.py
```

Скрипт делает всё: генерирует NDK-стабы, кросс-компилирует `libcyberdrift.so`,
линкует ресурсы/манифест через `aapt2`, собирает выровненный APK, подписывает
(v1 + v2) и проверяет результат (`aapt2 dump badging`, `zip integrity`, выравнивание
`resources.arsc` — должно быть `stored`, иначе Android 11+ откажется ставить).

Эквивалентная команда для одного шага (для отладки):

```bash
zig cc -target aarch64-linux-android -nostdlib -shared -O2 -I src -I third_party \
    src/*.c -o build/jni/arm64-v8a/libcyberdrift.so
```

## Структура

```
src/            движок и игра (C99, без зависимостей)
  cd_mesh.[ch]  процессорная генерация мешей (бокс, цилиндр, икосфера, кольцо, луч)
  cd_kit.c      «кит» низкополигональных ассетов: ховеркрафт, здания, кристаллы, пилоны
  cd_track.c    процедурная трасса: центр, ширина, кривизна
  cd_game.c     стейт-машина, физика дрейфа, камера, стриминг мира, частицы
  cd_render.c   GLES2-рендерер, 6 шейдеров, атлас шрифта, HUD-примитивы
  cd_font.c     растровый шрифт 8×8 (генерируется в 4× атлас)
  cd_ui.c       HUD, титульный экран, пауза, финал
  platform_android.c  NativeActivity, EGL-контекст, тач-ввод
app/            манифест, ресурсы, иконки
tools/          сборка APK, генерация стабов, иконка, оффлайн-превью
docs/           иконка и скриншоты
```

## Как проверялась картинка без устройства

В песочнице нет GPU/EGL, поэтому движок прогоняется через `tools/gltrace.c` —
мок GLES2, который пишет реальный поток вызовов отрисовки в бинарный трасс,
а `tools/rasterize.py` (numpy) растеризует его в PNG с теми же шейдерами,
что и на устройстве (освещение, фог, fresnel, альфа-смешивание, UI-атлас).

```bash
gcc -std=gnu11 -O1 -I src -I third_party -I tools -o /tmp/tracer \
    src/cd_mesh.c src/cd_kit.c src/cd_track.c src/cd_font.c src/cd_render.c \
    src/cd_game.c src/cd_ui.c tools/gltrace.c tools/preview_log.c tools/trace_main.c -lm

/tmp/tracer /tmp/play.trace play 240 2>/dev/null | head -1
# camera pos=(...) look=(...)
python3 tools/rasterize.py /tmp/play.trace /tmp/play.png 1280 800 "cx,cy,cz" "lx,ly,lz"
```

Доступные сцены: `play`, `menu`, `pause`, `gameover`, `showcase`, `assets`.

Именно так были найдены и исправлены реальные баги рендера: порядок инициализации
(стейт игры затирал рендерер), инвертированная намотка примитивов, отключённый
двусторонний свет, неверные UV глифов, слишком крупные стены каньона, камера под
полом в меню и «взрыв» частиц у камеры.
